# 開発引き継ぎ・保存運用（2026-10-20）

対象：人生シミュレーションゲーム「2000年の地球上の誰か1人。」

## ブランチの役割

- `main`：2026-10-15時点のプレイ可能な旧試作を保持する。現在の開発仕様へ準拠した完成版ではない。
- `develop`：Claude側で制作している最新版のコードを受け取り、検証するための作業ブランチ。最新ソースの取り込み前に `main` を直接上書きしない。
- 最新版を取り込んだ後、テスト・仕様照合を終えてから、Pull Requestを経由して `main` へ反映する。

## 確認済みの資料と注意

旧試作の `src/data.js` と `src/engine.js` は6能力・各0〜300を使う。旧試作の `README.md` には3か月刻みの進行、仮の地域6例、保存・再開などを記載している。

2026-10-20の新しいイベント仕様書では、人物の4能力（体力・知識・意欲・魅力）各0〜1000、気質5連続軸と表示32タイプ、イベントの3基本区分（自動／小さな選択／大きな選択）、14ジャンル、月次進行との接続が前提となっている。

「京都の暮らし 見本(3).html」にはこれら新しい機構に対応する画面・処理の試作コードがあるが、これだけをゲーム全体の最新版と断定しない。HTMLには画像・フォントがデータとして埋め込まれているため、公開前に権利・サイズ・分離方法を確認すること。

## Claudeによる最新版の登録手順

1. Claudeで実際に編集している**最新版のプロジェクト一式**（HTML、JS、CSS、画像等、依存設定、テスト、必要な資料）を確認する。見本HTMLだけで全ファイルを置換しない。
2. 現在の `develop` ブランチへコミットし、変更したファイルと作業日時を明記する。既存試作の動作・記録・資産を保持し、不明点は未確定として報告する。
3. `npm test` と `npm run check` を、新しいコード構成で実行できる場合は実行する。動作確認できなかった項目は「未実施」と書く。スマートフォンの表示、年次／月次進行、回答待ち停止、保存・復元と二重適用を優先確認する。
4. `develop` から `main` へのPull Requestを作成し、変更概要・実装済み・未実装・既知の不具合・検証結果を記載する。レビュー完了まではマージしない。

## セキュリティ・公開設定

リポジトリが公開状態の場合、`develop` にアップロードしたファイルも公開される。非公開にしたいコード、埋め込み鍵、秘密情報、再配布条件が未確認の素材を公開しない。公開範囲を確かめてからアップロードする。

この文書の登録は、最新版ソースの取り込み・実行・動作検証の完了を意味しない。
