# 依頼書：「状態の変化」の設計（2000年の地球上の誰か1人。／日本版プロトタイプ）

作成日：2026-10-20　／　依頼先：ChatGPT（設計担当）　／　実装担当：Claude（設計が確定してから実装）

## 0. この依頼のゴール
イベント140件の詳細設計案（v0.1）には、「食料が減る」「修繕計画を始める」「転居を検討する」など、**能力値・好感度以外の状態を変える指示**が合計142項目（124種類）あります。現在のプロトタイプにはそれを受ける仕組みが無く、イベントの文章では語られても、ゲーム内の状態は変わっていません。

この依頼では、**それらの状態を受ける仕組み（状態システム）を設計**してください。コードは書かなくて構いません。実装は私（Claude）が行うため、**迷わず実装できるデータ・ルール・数値の形**で出してください。

## 1. ゲームの前提（変えないでください）
- ゲーム：人生シミュレーション。誕生から死まで、境遇の違う誰か1人の人生を体験する。日本版プロトタイプは「京都の暮らし 見本」（スマホ縦画面、1つのHTMLファイル、画面はすべて日本語）。
- 時代・地域：現在の試作は京都のみ。**時代・地域の考証は未実施**です。設計時に時代に合わない前提（通貨、制度など）を置く場合は、そう明記してください。
- 開発者はプログラミング初心者のため、設計は専門用語を避け、数値と文章で説明してください。
- 全体方針：**不明点や矛盾があれば、推測で進めず質問を明記**してください。数値の調整は、仮の値を示した上で、確定は開発者に確認します。

## 2. 現在の仕組み（これに合わせて設計してください）
- **能力**：0〜1000の数値。★1〜5の評価。
- **気質**：5軸（方向と強さ）。
- **人物**：役割ごとに新規生成（家族・友人・知人・近所・仕事仲間・師・想い人・地域の人・旅人・教え子・子ども・新しい家族）。上限18人。初期好感度は8（新しい家族のみ40）。好感度の上限は100。
- **イベント**：自動（年齢帯ごと、変化量 ±1〜2）、小さな選択（±3〜5）、大きな選択（±6〜10）。1人生あたり自動約46、小さな選択約13、大きな選択約12。
- **後日談**：選択のあと一定期間後に一度だけ届く。種類は A 条件成立（判定なし）／B 返事・承諾（成功率あり）／C 他の仕組み依存（文章のみ）／D 保留／E 成果。成功率は基本50％、相手の好感度（最大±20％）と意欲（最大±10％）で補正、20〜80％に収める。
- **生活方針**：交流・学び・仕事・家族・休養の5つ。該当ジャンルのイベントが出やすくなる。
- **保存**：ブラウザ内に保存。再開しても引き直さない・二重処理しない。旧セーブも読み込める必要がある。
- **健康**：死亡確率のみ（病気や怪我の種類・期間は無い）。
- **無いもの**：お金・食料などの資源、住居、職業の段階、結婚・出産・自分の子、家計・報酬、資格。

## 3. すでに確定している方針（ユーザー指定）
1. 変化量の幅：小さい変化 ±1〜2、中程度 ±3〜5、大きい変化 ±6〜10。ランダムは各範囲内。
2. 能力値を一律3倍にする処理は採用しない。活動による成長と、一時的な変化は区別する。
3. 確率判定が必要な標準的行動は基本成功率50％。技能・準備・相手の事情による補正は可。条件だけで成立する結果には成功判定を設けない。
4. 追加しやすく安全な作り：データ検証、ID重複検査、保存互換、二重処理防止。重要なイベントや回答待ちのイベントに不備がある場合は、黙って消さず報告する。
5. 範囲は140件すべて。

## 5. 設計してほしいこと
### 5-1. 状態システムの切り分け
上の124種を、**いくつの状態システムにまとめるか**を提案してください（個別に124種作るのは現実的ではありません）。各システムについて次を示してください。
- 何を記録するか（項目名、取りうる値、初期値）
- どのイベント・マーカーがそこに書き込むか（マーカー名→書き込み内容の対応表）
- 読み出し側：その状態によって何が変わるか（イベントの発生条件、選択肢の出し分け、能力・好感度・死亡確率・文章など）

### 5-2. 優先順位と依存関係
- 作る順番の提案（他に依存しにくいものから）と、その理由。
- 特に「進行中の件」（探索・依頼・返事待ち・協議・予定・準備）は、共通の仕組み1つにまとめられるか。期限切れ時は、自然消滅か、失敗扱いか。
- 「資源（お金・食料・物資）」と「結婚・出産・家計・報酬」は一緒に設計すべきか、分けられるか。

### 5-3. 数値（仮でよいので提案を）
- 資源の単位、初期量（身分・職業・境遇で変わるか）、毎年の収入と消費の目安、不足時の影響。
- 住居の状態の段階と、修繕・転居の費用と期間。
- 職業と修業の段階、独立や転職の条件。
- 病気・怪我の種類と期間、回復の条件。
- 「体力-1（病態側を主処理）」など、病態側を主とする記述の扱い。
- 期限や持続期間（何か月で届く・切れるか）。
- **すべての数値は「仮」と明記**してください。確定は開発者の判断で行います。

### 5-4. 既存イベント140件との整合
- 現在の設計案の効果310項目のうち、能力・好感度は反映済みです。今後状態システムに接続するときに、**どのイベントの効果を差し替え、どの後日談の結果を状態変化に変える**かの一覧を出してください。
- 後日談C（他の仕組み依存）5件が、どの状態システムに接続されるかを示してください。

### 5-5. 時代・地域の考証

## 6. 設計案の制約（必ず守ってください）
- 保存データは旧セーブと互換性を保つ。新しい状態の項目は、**無い場合の初期値を決める**。
- 状態の変化は、**一度だけ処理され、再読み込みしても二重に適用されない**こと。
- 状態が壊れたとき（不明な値、範囲外）は、黙って無視せず報告できること。
- ランダム要素は、変化量の範囲（上記の確定方針）に収める。
- 実装の規模：まず最小の仕組みで動かし、後から追加できる形にする（段階導入が前提）。
